# Contributing

Thanks for your interest in contributing to a nfiniity project. This guide applies to all repositories under the [nfiniity](https://github.com/nfiniity) GitHub organization. Individual projects may add their own project-specific contribution guidelines on top of this one.

## Code of Conduct

All contributors are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md). Be respectful, constructive, and welcoming.

## Ways to Contribute

- **Report bugs** — open an issue in the relevant project repo with a clear reproduction
- **Suggest features** — open an issue describing the use case before opening a large PR
- **Improve documentation** — typo fixes, clarifications, and examples are always welcome
- **Submit code** — bug fixes and small enhancements via pull requests

## Filing Issues

Before opening a new issue:

1. Search existing issues to avoid duplicates.
2. Use the project's issue templates where available.
3. Include enough context to reproduce: version, environment, steps, expected vs. actual behavior.

## Pull Requests

1. **Fork** the repository and create a feature branch from the default branch.
2. **Keep changes focused** — one logical change per PR. Smaller PRs are easier to review and merge.
3. **Match the existing style** — follow the conventions already used in the codebase.
4. **Update tests** when changing behavior, and ensure existing tests still pass.
5. **Update documentation** when changing public APIs or user-visible behavior.
6. **Write a clear PR description** — what changed, why, and how it was tested.

For larger changes, please open an issue first to discuss the approach before investing time in an implementation.

## Security Issues

Please **do not** open public issues for security vulnerabilities. See our [Security Policy](SECURITY.md) for private disclosure instructions.

## Questions

For general questions, open a discussion on the relevant project repo or reach out via [info@nfiniity.com](mailto:info@nfiniity.com).
